## アーキテクチャパターン

### MVVM + Repository パターン
- **Model**: データ構造とビジネスロジック
- **View**: UI画面（screens + widgets）
- **ViewModel**: Provider による状態管理
- **Repository**: データアクセス層の抽象化

### データフロー
1. View → Provider（ユーザーアクション）
2. Provider → Service（データ操作要求）
3. Service → Database（データ永続化）
4. Database → Service → Provider → View（データ更新通知）

## 主要コンポーネント

### Models
- `HealthRecord`: 全体的な健康記録データ
- `MoodRecord`: 気分・日記データ
- `MenstrualRecord`: 月経関連データ
- `Settings`: アプリ設定データ

### Screens
- `HomeScreen`: カレンダー・サマリー表示
- `HealthRecordScreen`: 体調記録入力
- `SettingsScreen`: 各種設定

### Services
- `DatabaseService`: SQLite操作
- `HiveService`: 設定データ操作
- `ChartService`: グラフデータ生成

## 状態管理戦略
- Provider パターンを使用
- 各画面ごとにProviderを分離
- Consumerを使った効率的な再描画
